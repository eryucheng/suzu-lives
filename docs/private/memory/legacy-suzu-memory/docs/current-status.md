# Suzu Memory 当前实现状态

本文只记录当前已经落地的能力和明确边界，不保留早期试跑或历史基线。最后按代码整理：2026-08-09。

## 当前入口

| 入口 | 用途 |
| --- | --- |
| `@suzu-memory/service` | 所有业务能力的统一门面。 |
| `@suzu-memory/host-adapter` | 将通用聊天轮次映射为回复前召回、回复后归档、失败清理和空闲维护。 |
| `@suzu-memory/sdk` | 嵌入式 Service 与 HTTP 客户端。 |
| `@suzu-memory/cli` | 本地初始化、处理、搜索、审核、备份和恢复。 |
| `@suzu-memory/server` | 本地 HTTP API 与审核台托管。 |
| `@suzu-memory/console` | 仅通过 Server API 工作的本地审核台。 |
| `@suzu-memory/config` | 便携 JSON 配置与 Provider 装配。 |

## 已实现

### 事件、证据与长期记忆

- 版本化事件协议、主要用户/Agent 身份边界、`eventId` 幂等接收和六类事件类型；
- `amend`、`supersede`、`retract` 修订链；失活事件和来源退出有效提取与召回，但保留审计；
- 事件发生、获知、记录、状态生效与失效时间分离；
- 物理、关系、虚构、梦境、假设和未知世界框架；
- 超长事件按自然边界无损分片；完整片组只会整体领取并在模型前还原；
- 输入批次总字符预算、Worker 租约、过期回收、显式恢复和旧 Worker 写回防护；
- 三段式聊天归档窗口：只读前文、可成为证据的核心区、只读后文；
- 原始 `utterance`、低层事件、结构化状态、来源与关系分开保存；
- 用户、Agent、第三方、共同经历、主题和事件簇的可重叠归属；
- `episode` 与 `topic` 的独立高层结构，旧 `topic_or_episode` 仅保留读取兼容；
- 当前状态、历史状态、范围例外、纠正和反证可以共存。

### 维护与高层整理

- 新节点落库后立即执行不依赖模型的关系归属、关联图更新和巩固计划；
- Embedding 按节点和检索表达内容哈希增量生成，支持重建；
- 检索表达只在正文不足以独立检索时调用专职模型，派生表达不改写原节点；
- 人物状态分为身份、观念、偏好、习惯、行为倾向、价值、目标、能力、关系、情绪联结、自我认识和现实条件等家族；
- 状态、结构、关系和回顾性巩固使用独立 Schema 与证据门禁；
- 同阶段、同状态族的专职字段可组合为一次结构化调用，但仍逐字段验证；
- 状态分析、维护任务和巩固运行都具有持久化重试、租约和失败审计；
- 自动尝试耗尽后保留基础证据与可用部分候选，转入人工审核，不阻塞同批其他工作；
- 仅本人明确 `reported` 状态的新建或补强，在证据边界完整时可确定性自动接受；其他高层结论默认待审。

### 检索

- BM25、CJK/英文词法、向量、实体、时间和状态多路候选；
- 结构化长期记忆与逐字情景证据双通道召回；
- 主体、世界、生命周期、当前/历史状态和证据边界硬门禁；
- 多种子汇聚、有界图传播、扇出抑制、无匹配门槛和渐进式上下文拼装；
- 原话、依据、反证、时间线、关系和因果问法的专门展开路线；
- 关系因果边只在明确因果问题中读取；
- 正式 Service 默认开启有下限的自然衰退与有界再激活；两者只影响通过门禁后的普通候选排序，不删除记忆；
- 明确主体、实体、时间和内容高度吻合的精确回忆可绕过普通衰退扣分；
- 检索轨迹、最终回复绑定、下一条用户反馈和显式反馈信号均可持久化。

### 管理、审核与恢复

- 记忆列表、详情、编辑、软删除与恢复；
- `ingestion`、`reported-state`、`structure`、`relation`、`maintenance-failure` 五类统一审核；
- 审核台展示候选内容、当前状态、成员/端点、原始证据、阻塞事件、输入批次、维护失败和备份健康；
- 只允许安全撤销尚未被后续修改的已接受关系；
- SQLite 一致性快照、SHA-256 清单、完整性检查、离线恢复前自动备份和 Agent 作用域确认；
- 外部模型用量的追加式流水记录；
- 结构化记忆图快照。

### 通用聊天宿主接入

- `beforeReply`、`afterReply`、`abortReply`、`onIdle`、`onSessionEnd` 完整生命周期；
- `hostId + sessionId` 生成内部运行时会话作用域，避免跨宿主同名会话相互覆盖；
- 回复前返回原始长期记忆上下文与检索轨迹，宿主自行决定如何注入模型；
- 回复后以稳定 ID 归档双方最终消息；失败轮次不会写入不存在的 Agent 回复；
- 宿主可显式跳过某轮长期召回，避免把上一轮轨迹错误绑定到当前回复；
- 可选的 `skip / recall` 介入策略可由宿主启用，但不是记忆内核的强制行为。

## 默认策略

- `MemoryService` 默认开启自然衰退和正式命中后的有界再激活；
- 原始证据、事实真值、主体、置信度和基础边权不因衰退或召回而被改写；
- 外部反馈的奖励归因、节点可访问性学习、关系效用学习和情绪排序偏置均默认不自动应用；
- 只有调用方显式给出策略版本、范围和上限时，已审核的可塑性或情绪偏置才会参与排序；
- Core 不创建 Cron、后台常驻 Worker 或定时器，宿主决定处理和维护时机。

## 已知边界

- 事件协议、宿主适配合同、Provider 合同和数据库兼容性仍是预览接口；
- 外部 rerank Provider 尚未形成统一配置与正式生产接线；
- Retriever 当前仍会将本 Agent 的活动节点与历史状态加载到 JavaScript 中完成候选融合；面向数万节点的 SQL 侧候选裁剪尚未完成；
- 公开的合成陪伴对话数据与干净机器发布验证尚未完成；
- 根包和工作区包仍以本地开发形式维护，尚未承诺稳定发布版本；
- 使用 `node:sqlite` 的 Node 运行时可能输出实验性警告；仓库声明的最低版本为 Node.js `22.5.0`。
