# Suzu Memory 架构

Suzu Memory 是本地优先的结构化长期记忆引擎。它从“宿主交来一条已确定的消息或活动事件”开始，到“返回有边界、可追溯的长期上下文”结束。

短期上下文由聊天宿主维护；本系统负责事件归档、长期整理、检索与审核。

本文描述当前代码的稳定结构。具体可用状态见 [current-status.md](current-status.md)，评测结果见 [benchmark-status.md](benchmark-status.md)。

## 已实现的长期记忆特点

这套系统的目标不是把聊天记录压缩成一页“人物简介”，而是在不丢失可核对证据的前提下，逐步形成可修正、可联想、可追溯的长期认识。当前已经接通的特点如下。

| 特点 | 实际机制 |
| --- | --- |
| 原文与理解并存 | 原始 `utterance`、事件、持续状态、事件簇和主题分别保存。结构化结论不能替代原话；结构化提取漏掉某次经历时，逐字情景证据仍可独立召回。 |
| 认识人，而不是只抽关键词 | 状态层将身份、观念、偏好、习惯、气质、价值、目标、能力、关系、情绪联结、自我认识和现实条件分开处理，并要求主体、范围、时间与来源证据同时成立。 |
| 关系与共同历史有独立位置 | 每个 Agent 都有主要用户、Agent 本身和两者的持续关系容器；具体关系判断仍带方向和观点主体，不会把一方对另一方的认识倒置。 |
| 多世界、三种时间与状态换代 | 现实性、世界框架、事情发生/获知/记录时间和状态有效期是独立字段。新观念不会覆盖旧证据，纠正、例外、暂停和完成都保留历史链。 |
| 长消息也保留完整语义 | 超长输入按自然边界无损分片，处理时必须恢复完整、连续的逻辑事件才交给提取流程；窗口前后文只能帮助理解，不能重复成为新证据。 |
| 分层、节制地建构记忆 | 先无模型地保存证据、做确定性归属和任务登记；再增量生成向量；最后才由带 Schema 的专职语义流程分析状态、结构或巩固。高层判断失败也不会抹掉已保存的低层经历。 |
| 受边界约束的联想图 | 新记忆会在同一世界内建立线程、实体、时间和语义关联，并触发有预算的回顾性巩固计划。召回使用多种子汇聚、关系视图和扇出抑制，不会从一个高频人物节点无边界蔓延。 |
| 有下限的遗忘与再激活 | Service 的产品默认值会让普通、久未触及的候选轻微降权，同时让被正式召回的记忆有限增强；两者都不会删除记忆，也不能压过明确主体、实体、时间和内容的精确匹配。 |
| 可恢复的长期整理 | 输入批次与维护任务都使用幂等、租约、过期回收和有界重试。模型或网络失败时，原文和已成功的低层结果保留，失败的高层任务会隔离到审核，而不是让后续记忆队列一起停住。 |
| 可审计、可纠正 | 每个结论都能回到原始证据、输入批次、审核提案、检索轨迹和生命周期操作。模型只能提案，人工决定可直接复用已保存证据，不需要重新猜一遍。 |

后文分别说明这些机制所在的层级和边界。这里的“已实现”只指正式运行链路；反馈驱动的可塑性实验虽然已有持久化和影子运行基础，但默认不会自行改写正式记忆或排序。

## 分层与依赖方向

```text
聊天宿主 / 自定义 Runtime
        │
        ├── @suzu-memory/host-adapter
        ├── @suzu-memory/sdk
        ├── @suzu-memory/cli
        └── @suzu-memory/server ── @suzu-memory/console
                          │
                  @suzu-memory/service
                          │
  ingestion · maintenance · extraction · analysis · structurer
  embedding-indexer · retriever · visualization · usage-ledger
                          │
                   @suzu-memory/core
                          │
                SQLite + FTS5 + 向量记录
```

`@suzu-memory/service` 是统一业务门面。CLI、Server、SDK 与宿主适配层都通过它调用能力；领域包不反向依赖 CLI、Server、SDK 或特定宿主。

| 模块 | 当前职责 |
| --- | --- |
| `runtime` | 解析数据根目录、Agent 作用域与本地路径。 |
| `config` | 读取便携 JSON 配置，装配 Service 和 Provider。 |
| `service` | 统一初始化、写入、维护、检索、审核、备份与图快照入口。 |
| `ingestion` | 标准事件校验、幂等写入、分片、归档窗口与输入批次处理。 |
| `extraction` | 从有边界的原始证据中提出低层长期记忆候选。 |
| `maintenance` | 协调零模型整理、Embedding 与语义维护队列。 |
| `analysis` | 分析人物状态及其证据、时间、范围和变化。 |
| `structurer` | 提出事件簇、主题、因果和回顾性巩固候选。 |
| `embedding-indexer` | 为可召回节点和逐字证据增量生成检索表达与向量。 |
| `retriever` | 解析查询、多路候选、硬门禁、图传播和上下文拼装。 |
| `core` | SQLite Schema、事务、记忆/关系/证据/审计和数据约束。 |
| `providers` | 结构化生成、Embedding、错误与用量信封的协议适配。 |
| `usage-ledger` | 追加式保存外部模型的原始用量事件。 |
| `visualization` | 导出结构化记忆图快照。 |
| `evaluation` | 回归、研究与公开数据集评测；生产运行不依赖它。 |

Provider 只处理请求、响应、结构化输出和用量，不读取数据库，也不拥有记忆业务规则。Core 不调用外部模型。

## 记忆空间与身份边界

每个 `agentId` 对应一个隔离的本地数据作用域。初始化时，Service 会确定性建立：主要用户实体、当前 Agent 实体，以及两者之间的主关系容器。

关系容器代表“这段持续关系及其共同历史”，不是一条关系状态摘要。称呼、信任、边界、共识等具体关系理解仍作为带主体、时间和证据的 `relationship` 记忆保存。

标准事件的 `actor` 只能是主要用户或当前 Agent；第三方作为 `participants` 中的 `other` 出现。事件参与者不自动成为长期记忆主体，主体仍须由原始证据和代码门禁确认。

### 世界、现实与时间

世界框架与真实性是不同维度：

- `world.frame` 可为 `physical`、`relational`、`fictional`、`dream`、`hypothetical` 或 `unknown`；
- 记忆节点的 `reality` 可为 `real`、`hypothetical`、`fictional`、`roleplay` 或 `unknown`；
- `event_time` 表示事情发生时间；`known_time` 表示 Agent 获知时间；`recorded_time` 表示系统记录时间；状态另有 `valid_from` / `valid_to`。

因此，关系世界中的共同经历可以是 `reality=real`，而虚构、梦境和假设不会因文本相似度混入现实回忆。

## 持久化模型

系统不把整段对话当成唯一检索单元，而是保存互相连接的五类持久对象。

| 对象 | 用途 |
| --- | --- |
| 输入事件 | 宿主追加的原始业务事件及其修订、分片和处理状态。 |
| 原始证据 | 可逐字核对的 `utterance` 与来源信息。 |
| 记忆节点 | 具体经历、状态、主题、事件簇、计划等可召回内容。 |
| 关系与归属 | 时间、证据、状态换代、实体、主题、事件簇和因果关系。 |
| 运行与审计 | 输入批次、维护任务、审核提案、检索轨迹、反馈、用量与快照信息。 |

当前节点类型包括：

```text
utterance · event · episode · fact · belief_state · preference
relationship · plan · commitment · open_loop · derived_hypothesis
topic · reflection
```

`episode` 与 `topic` 是图中的高层结构节点：前者有现实时间边界，后者描述跨事件的语义主题。两者都是可重叠的高层节点；同一低层记忆可以同时归属某个人、双方关系、多个事件簇和多个主题，不受单父节点树限制。

### 持续认识维度与历史

`event`、`episode` 与 `topic` 记录“发生过什么”；状态层记录“一个主体在一段时间内是怎样的、相信什么、在意什么，以及和谁处于怎样的关系”。两者并存：一次具体经历可以支持某个持续认识，但不会因为一次发生就被夸大成稳定人格。

当前代码将持续认识分为以下十二个维度：

| 维度 | 状态家族 | 保存的认识边界 |
| --- | --- | --- |
| 身份与生平 | `identity` | 身份、背景与生平事实。 |
| 观念 | `belief` | 主体当前或历史的看法、理解与判断。 |
| 偏好 | `preference` | 在存在选择空间时的喜好、厌恶与选择倾向。单纯出现频率、被迫行为或便利条件不足以推出喜欢。 |
| 习惯 | `habit` | 带场景和条件的重复行为规律；可以是习惯，而不必是偏好。 |
| 气质与应对倾向 | `disposition` | 跨情境的交流、决策、行为与应对方式；单一事件不能单独定性。 |
| 价值与优先级 | `value` | 明确原则与真实取舍共同支持的价值判断。 |
| 目标与未完事项 | `goal` | 目标、意图、承诺、进度与开放循环。 |
| 能力与熟练度 | `capability` | 任务范围、表现结果、独立程度与依赖条件。 |
| 关系认识 | `relationship` | 有方向、观点主体和范围的角色、称呼、信任、边界与共识。 |
| 情绪联结 | `affective_association` | 触发对象、体验主体、情绪类型、直接依据及其时间变化；不把一时情绪改写为永久事实。 |
| 自我认识 | `self_concept` | 主体本人表达的自我理解、角色理解与人生叙事。 |
| 现实条件 | `condition` | 有时间和情境范围的条件、需求、约束或状态。 |

每条状态都保留主体、适用范围、现实性、来源证据、三种时间和有效期。`relationship` 还保留观点主体与关系方向，因此“甲认为乙可靠”不会被偷换成“乙认为甲可靠”。

偏好有更细的证据等级：`no_conclusion`、`situational_tolerance`、`selection_tendency`、`stable_preference`、`direct_preference` 与 `explicit_rejection`。它让系统能够表达“可以接受”“有选择倾向”“稳定喜欢”和“明确喜欢”的差别，并允许反证挑战或降低已有推断。

状态表示层分为 `reported`、`inferred` 与 `established`：

- `reported`：主体明确表达的状态；
- `inferred`：系统基于有界证据形成、可被纠正的推断；
- `established`：经过更高层验证或人工确认的状态。

同一个语义键在不同表示层、范围槽和时间段可以并存。状态更新、纠正、暂停、完成、取消、例外和关系撤销通过关系与生命周期记录表达；新认识不会覆盖原始证据，旧状态也会保留为具有有效期的历史。

复杂的持续认识不会交给一次无边界的模型判断。语义维护会按状态家族使用专职的结构化分析合同：共同核对证据来源、主体归属、适用范围、时间变化和当前状态关系；偏好还会单独区分明确表达、主动选择、重复行为、积极分享与反证。每个分析只读取其证据快照并产出受约束提案，而不是让模型直接改写既有状态或原始对话。

当基础证据足以保存、但更高层判断尚待人工确认时，系统可以保存隔离的 `provisional` 临时印象。它只作为带提示的单点候选参与受限召回，不参与正式图传播、巩固、衰退、再激活或反馈学习；审核结束后立即退出召回。

## 写入与维护

```text
事件接收
→ 本地协议/身份/世界校验
→ eventId 幂等追加
→ 超长事件无损分片
→ 按完整逻辑事件领取输入批次
→ 语义归档窗口还原与提取
→ 原始证据、低层节点、来源关系
→ 零模型即时整理
→ 持久化后续任务
→ 语义维护 / Embedding 维护
→ 提案审核或受限自动接受
```

### 事件与归档窗口

事件是追加式的。`amend`、`supersede` 与 `retract` 生成修订链，不覆盖原事件；失活来源退出后续提取和召回，但保留审计。

单事件超过配置的字符上限时，会按自然边界拆成带父事件、序号和字符区间的片段。领取时片组必须完整、连续且能整体放入批次预算，才会还原后送入提取模型；系统不会静默截断半条消息。

正式聊天归档使用三段式窗口：

```text
只读前文衔接 | 本次可成为证据的核心区 | 只读后文衔接
```

只有核心区获得证据编号并可生成候选。前后文只用于理解指代和未完成事项，不会重复归档为新证据。多个窗口可共享一次模型请求，但候选来源不得跨窗口；只有宿主明确声明连续性时才建立跨段相邻关系。

### 三条维护通道

| 通道 | 是否调用模型 | 处理内容 |
| --- | --- | --- |
| 零模型即时整理 | 否 | 主关系归属、关联图、安全巩固计划和后续任务登记。 |
| Embedding 维护 | 是 | 为新增或检索表达变化的节点增量生成向量；内容哈希相同则复用。 |
| 语义维护 | 是 | 检索表达、人物状态、结构/关系候选与回顾性巩固。 |

语义任务按职责使用各自的 Schema、提示词、证据快照和审核规则。系统不会把状态、结构、关系和检索表达混成一个无边界的大提示词。

输入批次、维护任务与回顾性巩固运行都具有持久化领取状态、租约、过期回收和有界重试。技术失败不会删除已归档的原始证据：能够保留的低层结果会保留，无法自动完成的高层升级进入审核台并记录错误原因。

### 图关联与回顾性巩固

零模型即时整理会先把正式记忆纳入持续关系容器，并在同一世界内增量维护几类可解释的边：`same_thread`、`shares_entity`、`timeline_next` 与 `associated_with`。自动语义关联有相似度门槛和每个节点的度数预算，时间边还要求时间顺序与内容相近；它不会仅因两个词相似就跨世界接线。

每次新增正式记忆还会以它为起点做一次有深度、候选数和边权预算的局部回看，产生持久化的巩固运行计划。后续语义维护可以据此提出事件簇、主题、关系或因果结构，但原始节点和原始证据不被重写。这样，新经历可以让旧经历在事后形成新的关联，同时错误关联仍可审核、驳回或撤销。

## 审核与安全落库

模型只能提出受约束候选，Core 在落库或接受时再次校验证据、主体、世界、来源生命周期、状态槽和关系端点。

统一审核入口覆盖：

- `ingestion`：低层候选的人工决议；
- `reported-state`：人物状态提案；
- `structure`：主题与事件簇提案；
- `relation`：因果关系提案；
- `maintenance-failure`：耗尽自动尝试后的任务或巩固运行。

只有来源、说话者和主体完全一致的本人明确 `reported` 状态，且动作仅为 `create` 或 `reinforce` 时，才允许确定性自动接受。状态变化、冲突、行为推断、结构、关系和来源不完整的候选默认待审。人工接受或驳回复用已有候选和证据，不重新调用分析模型。

## 召回

```text
查询
→ 解析意图、时间、主体与世界范围
→ BM25 / n-gram / 向量 / 实体 / 时间 / 状态候选
→ 主体、世界、生命周期与状态硬门禁
→ 结构化节点与逐字情景证据双通道融合
→ 多种子汇聚
→ 有界图传播与扇出抑制
→ 当前/历史状态补全、证据下钻
→ 受预算限制的上下文片段
→ 检索轨迹与正式命中再激活
```

几个关键边界：

- 没有候选达到门槛时返回无匹配，不强行注入无关记忆；
- 结构化状态优先回答稳定事实、偏好、关系和特质；在缺少合格状态时，才可由同主体原话作为“当时明确陈述”的有界兜底；
- 具体经历可通过逐字情景证据通道召回，即使结构化提取遗漏该事件；
- 原话、依据、反证、时间线与因果问题各走不同的受限展开路径；
- 因果边只在明确因果问法中读取，普通联想不会伪造因果；
- 向量生成后，相似度、融合和图传播都在本地执行，不再产生模型费用；
- Service 默认启用有下限的自然衰退和有界的“被正式召回后略微增强”。衰退只影响普通候选排序，不删除记忆，也不能压过明确主体、实体、时间与内容高度吻合的精确回忆。

图传播不是统一地沿所有边扩散。时间线、因果和联想使用不同关系视图：时间问题优先遵循前后顺序，因果问题只读取已接受的方向性因果边，普通联想才使用语义、实体和共同主题关系。多个较弱种子能够在同一节点汇聚；高连接节点的普通出边会按份额分配激活预算，只有纠正、替代等强制关系可绕过这种抑制。

检索轨迹保存候选路线、门禁、排序变化、传播路径和最终注入节点。它是审计与后续研究数据，不被当作生活记忆再次召回。

### 动态强度与可塑性边界

通过 `MemoryService` 的默认产品配置，普通候选会采用有下限的自然衰退；正式命中的记忆会记录有限、会随时间回落的再激活状态。这模拟“近期或反复想起的事更容易被联想”，但保留最低可达性，且不触碰原文、事实和状态生命周期。

代码还保存了检索反馈、回答绑定、奖励观测、节点信用、边路径信用和巩固强度等研究数据，并提供影子运行、版本化提案、重复应用防护与回滚接口。这一层用于以后校准“哪些路径真正帮助了回答”，当前默认只记录和预览，不会自动把亲昵、普通回复或一次偶然命中当作奖励并修改正式排序。

## 宿主生命周期

宿主只需映射自己真实拥有的时机：

```text
用户消息确定
→ beforeReply：可查询长期记忆，保存本会话召回头
→ 宿主生成最终回复
→ afterReply：归档双方消息，绑定轨迹与回复
→ onIdle / onSessionEnd：规划窗口，处理待办并维护
```

`hostId + sessionId` 会生成内部运行时会话作用域，避免不同宿主使用同一个会话名时覆盖检索轨迹。生成失败时使用 `abortReply`，不会归档不存在的 Agent 回复。

Suzu Memory 不内置 Cron、常驻 Worker 或聊天平台实现；调度频率和线程模型属于宿主。

## 存储、备份与对外接口

每个 Agent 的数据保存在本地 SQLite 数据库中，配合 FTS5、向量记录、追加式用量流水和缓存化图布局。向量可根据节点内容哈希增量生成，也可重建。

数据库备份使用 SQLite 一致性快照，并保留 SHA-256、Schema、Agent 身份和完整性信息。恢复是离线替换操作：需要确认 Agent 身份，且会先备份当前数据库；HTTP Server 只提供创建快照，不提供热恢复。

当前可通过以下方式接入：嵌入式 `MemoryService`、HTTP SDK 与本地 Server、CLI、通用 Host Adapter，以及 Server 托管的审核台和结构图快照。

标准事件协议、宿主适配合同、Provider 合同和数据库兼容性仍处于预览阶段；调用方应通过 Service、SDK、CLI 或 HTTP API 接入，而不要直接依赖 SQLite 表结构。
