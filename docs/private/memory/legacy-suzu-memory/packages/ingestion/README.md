# @suzu-memory/ingestion

标准陪伴事件进入结构化长期记忆的有界领域流水线。

- `protocol.mjs` 只负责身份、世界、时间和幂等事件接收；
- `archive-windows.mjs` 负责正式会话窗口：不重叠核心、只读边界衔接和 Provider 请求打包；
- `processor.mjs` 只负责批次领取、失败回退、成功归档和阶段顺序；
- `processing-stages.mjs` 分别实现长期提取、证据归档、零模型即时整理和用量记录；
- `index.mjs` 只暴露稳定的事件协议与批处理入口。

事件接收不调用模型。原事件保持追加式不可变；作者编辑、取代或撤回通过独立的 `amend`、`supersede`、`retract` 修订记录表达。失活事件不会再被领取，已归档来源会保留审计但退出有效证据；只由失活来源支撑的派生记忆会软删除。正在由 Worker 处理的事件拒绝竞态修订。

`processPendingEvents` 可以接收 `archiveWindows`，每个窗口用稳定 `id`、本次 `coreEventIds`、可选 `continuityId`、只读前文和只读后文描述。多个窗口可以共用一次提取调用，但候选来源不能跨窗口；只有相同显式 `continuityId` 的相邻分段会建立跨段 `followed_by`。正式宿主和所有公开评测都调用同一个 `createConversationArchiveWindows()` / `packConversationArchiveWindows()`，不会存在“评测专用的更强切窗逻辑”。不提交 `archiveWindows` 时保留低层 API 的单窗口兼容行为。

候选进入人工审核不再必然从召回中完全消失。证据主体来源存在可解释偏差，或 observed/inferred 人物状态正在等待 inferred 专职分析器时，只要主体和世界边界仍自洽，就会额外写入隔离的 `provisional` 临时印象并只登记 Embedding 任务；确定性关系整理、语义上下文、结构提案和巩固不会处理它。共同主体状态、世界混杂和持有者冲突等结构问题仍只进入审核，不生成临时节点。审核决议是临时召回资格的唯一真值，接受、修正接受或驳回都会使它退出候选。

已进入人物状态专职分析的候选同样遵守这条回退规则。模型或 Provider 处理失败会自动尝试最多三次；仍无法完成时，原始事件和 `utterance` 证据不变，原候选以 `provisional` 形式保留，并把已有入库决定转入统一人工审核。人工只接受或驳回现有候选，不重新触发专职分析模型；同一批次的其他候选继续处理。

长期提取调用本身也不会因为一次耗尽重试的临时传输故障卡死整条流水线。Provider 已经完成约定次数的网络、超时、限流、服务端状态或非法响应外壳重试后，处理器会用同一批次原子地归档完整 `utterance` 证据，把具体错误、诊断和尝试次数登记到统一维护失败审核队列，并将输入批次标记为“降级完成”；后续批次继续领取。密钥无效、请求参数错误等配置问题不走该降级路径，事件仍返回 `pending` 并明确报错，避免错误配置静默跳过全部长期提取。

超过单事件字符阈值的正文会先无损拆成带父事件和字符区间的幂等片段；领取时，同一父事件的片段被视为一个不可拆开的逻辑事件。完整片组能放入预算时整体领取，并在送入提取模型前还原为一条原始消息；当前批次剩余空间不足时整组留给下一批。片组本身超过事件数或正文字符预算、缺片或区间不连续时明确返回阻塞，不把半条消息送给模型。处理器把实际字符数写入批次审计，并在领取时写入 Worker 租约；正常失败会立即把事件退回待处理，进程被关闭或休眠后，过期租约会在下一次领取时自动回收。确认旧 Worker 已终止时，也可通过 CLI 或 HTTP/SDK 的显式恢复入口立即恢复。旧 Worker 无法提交已经被回收的批次。长期节点归档后只立即执行确定性的人物关系、关联图和巩固计划，并向 `@suzu-memory/maintenance` 登记 Embedding、检索上下文和结构提案任务；归档回合不再直接调用这些外部 Provider。
