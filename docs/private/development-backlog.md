## 待办

### ST-001：自定义表情包的语义理解与检索

- **状态**：等待前置条件
- **记录日期**：2026-08-17
- **恢复条件**：Suzu 的视觉形象确定，并产出首批可作为规范的官方表情素材后再启动。

#### 要解决的问题

当前聊天中发送的表情包会作为图片交给 Agent，并附有“按表情、情绪或反应理解”的说明；但收藏的自定义表情包只保存文件名、路径、格式和大小。Agent 不会预先知道收藏夹中每一张自定义表情的语义，也不能按“害羞”“安慰”“无语”等意图稳定地挑选它们。

#### 第一阶段范围

1. 导入自定义表情时，复用 Suzu Lives 现有的 `image-vision` 能力，生成可编辑的画面描述、情绪、适用语境、OCR 文字和关键词。
2. 将上述语义与表情包原始文件一起保存；发送表情时，把语义和图片一并交给 Agent。
3. 在表情包管理界面提供人工编辑入口，允许覆盖自动生成的描述或标签。
4. 先用描述与标签完成文本检索；表情包数量、召回质量和真实使用需求足够时，再评估图文向量检索。

#### 明确不做

- 不直接引入或部署完整的 Meme Search（Rails、Docker、PostgreSQL/pgvector）技术栈。
- 不在没有用户明确确认的情况下，对已有全部表情包批量发起视觉模型调用。
- 不把表情语义当作不可修改的模型结论；自动识别结果必须可人工修正。

#### 设计依据

- 现有 `image-vision` 能力足以承担首版导入识图，不额外创造模型接入。
- [Meme Search](https://github.com/neonwatty/meme-search) 可作为“自动描述 + 人工编辑 + 标签/语义检索”的产品参考，而非直接依赖。
- Suzu 形象与官方素材会决定描述语气、角色名称、表情分类和默认检索词；在它们确定前实现容易返工。
