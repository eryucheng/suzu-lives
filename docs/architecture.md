# 软件边界

Suzu Lives 是交付给最终用户的独立软件。功能代码、连接配置、缓存和运行数据都由软件自己管理；用户不需要下载、配置或维护额外的 Agent 脚本目录。

## 0. 安装、运行数据与 Claude 注册

Suzu Lives 的最终运行结构必须始终分成三层：

1. **软件安装目录**：由用户选择，例如 `D:\Apps\Suzu Lives`。这里放 EXE、打包后的能力代码、运行时和内置资源；能力代码只在软件中执行，不复制到 Claude 项目。
2. **软件数据目录**：默认位于 `%LOCALAPPDATA%\Suzu Lives`，也可以由软件提供迁移或改址能力。这里放用户设置、授权后的连接信息、日志、缓存、索引、备份和各能力运行数据；设置应由软件界面管理，而不是分散到 Claude 项目中的私有配置文件。
3. **Claude 项目注册目录**：内置能力只保留软件生成并维护的 `CLAUDE.md`、`.claude/skills/.../SKILL.md` 等轻量注册文件。它们声明如何调用 Suzu Lives，不承载功能源码、运行配置、缓存、密钥或记忆索引。用户明确导入的外部能力包是受限例外：当前 Claude 安装器可将其普通 Skill 文件树复制到自己的受管目录，但不会执行其中脚本；具体边界见 [外部能力清单](external-capabilities.md)。

注册文件不得写死软件安装绝对路径。安装、升级、移动或卸载软件时，由 Suzu Lives 维护稳定的本地启动入口和注册版本；Claude 项目只引用这个稳定入口。这样用户换安装位置时，不需要逐个项目重新配置技能。

## 1. 软件源码

开发仓库采用 `apps/` 与 `packages/` 的模块化结构。

- `apps/` 保存桌面端和以后可能增加的命令行入口。
- `packages/` 保存由软件实际运行、可被多个入口复用的能力代码。
- 新功能优先实现为 `packages/` 下的独立模块，再由桌面端调用。
- 新功能实现为软件拥有的源码、测试和必要的数据升级；用户运行时不依赖外部脚本目录。

建议的通用模块包括：

- `agent-registry`：登记已连接的 Claude 项目，并为其生成稳定的软件数据身份。
- `claude-integration`：在用户明确同意后安装、更新和诊断软件所需的 Claude 接入配置。
- `conversation-reader`：读取和搜索 Claude 会话，供软件内的会话查看器使用。
- `cost-ledger`：记录 API 原始用量并计算费用。
- `memory`：压缩、事件记忆、RAG 与查看器。
- `automation`：主动关心、定时任务与外部事件。
- `media`：识图、视频理解、绘图和语音。
- `device-bridge`：手机、邮件和摄像头连接。

## 2. 软件数据

正式安装后默认位于 `%LOCALAPPDATA%\Suzu Lives`，包括：

- 已连接 Claude 项目的身份和软件设置；
- API 用量流水；
- 日志、缓存、索引和备份；
- 各模块运行状态。

软件数据不写入安装目录，也不上传仓库。能力产生的数据必须写入这里或用户明确选择的位置。

## 3. 用户的 Claude 连接

默认 Claude Code 已由用户自行安装。用户只需要在软件中选择或确认需要连接的联系人 Agent 工作目录；软件在用户明确同意后，把必要的轻量注册文件写入该项目。该路径仅用于定位用户自己的 Claude 会话和进行经过授权的接入。

软件负责提供、升级和诊断自己的记忆、自动化、媒体和设备能力。Claude 项目不应成为这些能力的运行位置。

用户自己的 `CLAUDE.md`、人设和项目文件仍归用户所有；软件不得把这些私人内容复制进安装目录或仓库。
