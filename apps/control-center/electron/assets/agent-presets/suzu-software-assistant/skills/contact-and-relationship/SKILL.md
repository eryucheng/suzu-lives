# 已有联系人与相处设定

每位联系人都有独立的聊天记录、资料、记忆、附件、权限设置和已启用能力。创建联系人时加载 `contact-creation`；设置或更换联系人头像时加载 `contact-avatar`。

## 定位与资料操作

`suzu_contact_search` 按名称或联系人 ID 查找可见联系人，返回稳定 `contactId`、联系人工作区和三份标准资料的位置。`suzu_contact_read` 读取联系人概况或 `SUZU.md`、`persona.md`、`user.md` 的当前内容。`suzu_contact_update` 按 `contactId` 或唯一联系人名称直接更新联系人资料和常用设置；同名时根据工具返回的候选 ID 请用户确认。

用户已经明确给出唯一联系人名称和要填写的内容时，可以直接调用 `suzu_contact_update`。编辑现有长文本前先用 `suzu_contact_read` 读取对应部分，在当前内容上整理并保存。需要查看联系人位置、列出联系人或名称不确定时使用 `suzu_contact_search`。

联系人设置位于“对话 → 选中联系人 → ··· → 设置”。这里可以修改备注和头像，调整聊天显示、时间显示、审批模式和思考强度，并管理主动关心、长期记忆、本地附件以及微信和 QQ 连接。

审批模式包括“全权限”“工作目录可写”和“只读”。全权限适合用户信任且需要操作本机的联系人；其余模式用于限制可写范围或只允许读取。

相处设定位于“关系 → 相处设定”。页面固定提供三份资料：

- `SUZU.md` 是总设定，用来放角色与用户的关系、称呼、日常相处方式、当前情境与资料引用。
- `persona.md` 是角色本人的身份、核心动机、反应方式、语言风格和对话示例。
- `user.md` 是用户本人的资料、偏好与希望被如何对待的信息。

也可以添加其他 Markdown 资料；把它作为 `@文件名.md` 单独一行写进 `SUZU.md` 后，保存时软件会把它一并纳入这位联系人的设定上下文。

起草或编辑人设时，把角色自身的身份与处境、核心动机、情绪和行为反应、说话节奏与示例对话写进 `persona.md`；把角色与用户已经成立的关系、称呼和相处情境写进 `SUZU.md`；把用户本人的经历与偏好写进 `user.md`。优先使用能直接表现在对话里的具体描述。采用第二人称时，“你”指这位联系人，“用户”指用户；采用第三人称时整份资料保持同一视角。保存后的新一轮聊天会读取新内容。

主动关心与长期记忆的开关也在当前联系人的聊天设置。长期记忆的查看与维护位于“关系 → 记忆”，日记位于“关系 → 查看日记”。

联系人服务负责把名称或 ID 解析到对应工作区。填写已登记的联系人资料时使用上述联系人工具；本地文件工具用于用户明确要求处理其他自定义文件的情况。
