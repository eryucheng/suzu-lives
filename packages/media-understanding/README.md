# Media understanding

This package owns safe plans plus gated OpenAI-compatible executors for image vision and video understanding. It also owns the direct `suzu-lives image-vision` runtime used by the registered Agent Skill.

The direct image-vision command accepts one local image plus `--question`, `--config`, and `--no-retry`. Its configuration must be under `<dataRoot>/capabilities/image-vision/`; use `resources/image-vision.config.example.json` as the public schema reference. The bundled worker preserves Pillow-based EXIF transpose, bounded JPEG conversion, OpenAI-compatible request construction, neutral retry behavior, and `VISION_REFUSED` / `VISION_ERROR` boundaries. Temporary conversion files stay under the same software data root, and successful provider usage is appended through `@suzu-lives/cost-ledger` to the current Agent ledger.

The direct `suzu-lives video-understanding` command accepts one local video or `http(s)` URL plus `--question`, `--cache-key`, `--config`, `--no-cache`, `--keep-clip`, and `--dry-run`. Its configuration must be under `<dataRoot>/capabilities/video-understanding/`; use `resources/video-understanding.config.example.json` as the public schema reference. The bundled worker preserves FFmpeg/FFprobe verification, three-stage MP4 compression, the Base64 size boundary, content SHA plus question/cache-key caching, OpenAI-compatible `video_url` streaming/non-streaming response handling, stable JSON errors, and usage events in the current Agent ledger. Work directories, cache entries, and retained clips stay below the same software data root; `--dry-run` prepares and validates without requiring a key or contacting a provider.

The gated image/video executors remain separate: they read only their Suzu Lives configuration and require the registry gate, a private verified authorization context, concrete local-tool checks, and a software-provided safe credential resolver. The direct image-vision and video-understanding routes are the stable execution paths for their explicit Agent Skills. Tests use temporary data roots, fake commands, and local fake HTTP only.
