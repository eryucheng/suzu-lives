# Media understanding

This package owns the product-scoped executors for image vision and video understanding. Agent Core discovers their actions through the current contact's Suzu product Skills, calls `suzu_capability`, and lets the Electron parent invoke the executors with the validated contact scope and saved API connection.

The `suzu-image-vision` Skill declares the `image-vision.analyze` action. Its input contains `path` and optional `question`. Configuration remains under `<dataRoot>/capabilities/image-vision/`; use `resources/image-vision.config.example.json` as the public schema reference. The bundled worker preserves Pillow-based EXIF transpose, bounded JPEG conversion, OpenAI-compatible request construction, neutral retry behavior, and refusal boundaries. Temporary conversion files stay under the same software data root, and successful provider usage is appended through `@suzu-lives/cost-ledger` to the current Agent ledger.

The `suzu-video-understanding` Skill declares the `video-understanding.analyze` action. Its input contains `source` and optional `question`, `noCache`, and `keepClip`. Configuration remains under `<dataRoot>/capabilities/video-understanding/`; use `resources/video-understanding.config.example.json` as the public schema reference. The bundled worker preserves FFmpeg/FFprobe verification, three-stage MP4 compression, the Base64 size boundary, content SHA plus question caching, DashScope Qwen-VL/QVQ and Gemini native request formats, saved custom request templates, stable JSON errors, and usage events in the current Agent ledger. Work directories, cache entries, and retained clips stay below the same software data root.

The image and video executors remain separate. Electron capability adapters validate the active contact, resolve product configuration and credentials, invoke the selected executor, and keep model usage in the unified ledger. Tests use temporary data roots, fake commands, and local fake HTTP only.
