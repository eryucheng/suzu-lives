# @suzu-lives/memory-retriever

长期记忆的只读召回包。它读取 `memory-core` 的 SQLite 数据，返回可注入上下文、候选、图路径和可选持久化的召回轨迹；它不创建记忆、不接受待审提案，也不根据一次命中自动修改长期权重。

## 种子路线

普通查询先独立运行词法、实体和可选向量路线，再由确定性融合层建立候选：

- 精确短语或强词法可以独立放行；
- 强向量可以独立放行；
- 已审核实体名或别名的精确命中可以独立放行；
- 弱词法和弱向量只有同时达到各自最低门槛时才能互相佐证；
- 任意数量的弱分数不能靠相加绕过候选门禁。

明确日期查询和同会话续问锚点是专用确定性路线，不与普通混合候选争分。候选通过门禁后，图层才负责多种子汇聚、状态补全和受控扩散。

## 长期节点向量索引

`@suzu-lives/memory-embedding-indexer` 负责为正式长期节点建立增量索引，召回包只读取这些向量并生成本轮查询向量。索引器不会扫描原始会话，也不会把逐字 `utterance` 当作普通语义候选；原话仍只能沿证据下钻路线按需读取。

索引文本由代码从节点种类、标题、正文、主体、规范键、状态字段、时间和现实性等稳定字段生成，并保存内容哈希。节点没有变化时复用原向量；正式编辑导致关键字段变化时只重算对应节点。供应商失败不会删除已有可用向量，召回也会继续使用词法与实体路线。向量只负责提供候选种子，不能覆盖主体、时态、状态换代、证据来源或无匹配门禁。

逐字对话属于证据层，不参加普通状态、事件或主题问题的主种子竞争，也不会在事件摘要没命中时被拿来猜答案。只有用户明确追问“原话是什么”时，召回器才通过 `utterance` 路线读取原话；询问“有什么依据”时则从已命中的高层记忆沿审核过的证据边下钻。这样保留完整原文，同时避免一句措辞相似但语义无关的历史消息盖过已经整理过的长期记忆。

## 主体门禁

`resolveQuerySubject()` 只在查询中存在可保守解释的“我 / 你 / 我们 + 状态或行为谓词”时返回主体。开头的“你还记得”会作为对话套语移除；引号内语言、亲属称呼和没有明确谓词的代词不猜主体。`retrieveMemories()` 默认把当前说话者映射为 `user:user`，把被称呼者映射为 `agent:<agentId>`，也可通过 `queryPerspective` 显式提供别的键。

主体线索不能独立放行候选。它只执行两类硬门禁：

- 现代人物状态节点的结构化持有者必须与明确查询主体一致；
- `utterance` 的结构化说话者必须与明确查询主体一致。

事件、主题和普通事实可能涉及多人，因此角色缺失时保持中性；如果 `memory_actor_roles` 中存在匹配参与者，只在候选审计中增加 `subject` 路线标记，不凭主体给内容加分。主体解析、匹配候选和被硬拒绝候选的 ID 位于 `seedRouting.subjectRouting`，不会写回长期记忆。

该门禁还会延伸到联想图传播。明确询问某个人的状态时，另一人物的结构化状态不能沿普通关联、共同实体、共同主题或多种子汇聚重新进入结果；这类阻断记录在 `seedRouting.subjectRouting.hardRejectedGraphMemoryIds`。时间线和已审核因果链仍可合法跨人物，普通事件与多人参与记录也不按主主体粗暴裁掉。

## 当前状态与历史状态

历史状态不能在普通当前查询中独立回答。对于具备完整主体、语义键、表达层、状态家族和范围槽的现代状态节点：

- 明确询问过去，或调用方显式续问某个历史锚点时，保留历史焦点并补齐真实关联的当前状态；
- 普通查询先命中旧措辞时，把种子转发到精确的当前状态，只注入当前正文；
- 没有当前后继时，抑制该旧候选，不用过期内容猜现在；
- 结构不完整的旧迁移节点保持兼容行为，不根据正文推断生命周期。

`seedRouting.stateRouting` 记录本次处于 `historical-allowed` 还是 `current-only` 模式，以及被转发、被抑制的记忆 ID。转发不会改写数据库，也不会让状态关系额外加分。

生命周期边的数据库箭头与时间方向分开解释：`timeline_next`、`same_thread` 按旧到新保存，`corrects`、`supersedes`、`established_from`、`completes`、`cancels` 按新结果指向旧状态或来源保存。因此“之前呢”与“后来呢”会按关系类型选择相反的遍历方向；只有这种明确的时间线生命周期遍历可以读取 `superseded/disputed` 节点，其他关系视图仍只使用活跃节点。

时间线内的节点也按各自真实时间语义排序：事件使用 `event_start/event_date`，结构化状态使用 `valid_from`，缺失时才退回 `known_at/recorded_at`。晚补录的历史状态不会因此排到当前状态之后，状态正文前会显示“状态生效时间”。

结构化 `topic` 不以创建或更新时间占据事件时间线位置；旧的 `topic_or_episode` 也只有带明确事件时间时才具备时间节点资格。时间问句只在已经通过召回门禁的合格时间节点之间选择焦点，只有主题命中时不会沿时间边制造伪时间线。该选择记录在 `seedRouting.timelineRouting`，只保存节点 ID 与选择结果。

生命周期关系在自由联想中是非对称的：从旧状态走向当前结果属于真实性补全，不受普通扇出预算削弱；从当前结果反向联想到旧状态则是普通条件传播，会参与扇出竞争和阈值判断。明确时间线追问仍按关系时间方向处理。

对于明确个人主体的普通当前问题，如果当前结构化状态与保存它的较新原话同时命中，首层优先返回状态结论；原话仍留给证据下钻。事件、历史、原话和证据问题不使用这项优先。原话问句会先移除“说过什么、关于、的话”等固定骨架再执行原有词法门禁，说话者仍由主体门禁单独判断。

同一主体、`canonical_key`、状态家族和范围槽可以同时存在 `reported`、`inferred` 与 `established` 当前层。普通状态查询命中其中一层时，召回器会补齐同槽的其他活跃层并分别标注性质，不靠候选分数随机挑一层，也不自动裁决层间分歧。历史、依据、反证和原话查询保持单一焦点；带局部例外的状态先完成范围语义。补齐结果位于 `graph.representationCompletion` 和对应轨迹元数据。

明确询问“你为什么觉得 / 认为 / 判断……”时，召回器只在已经通过原检索门禁、且与当前命中状态完全同槽的候选中优先选择 `established`，其次 `inferred`，再沿该节点自己的证据边解释系统判断。问法不会单独召回另一条推断，也不会把 `reported` 的主体原话冒充系统推断依据。路由结果位于 `seedRouting.representationRouting`。

## 渐进式证据下钻

调用方可以在同一会话中保存上一条成功召回的类型化焦点，并只对短而不含新主题的续问提供 `anchorMemoryIds`。`trace.metadata.continuationFocuses` 分开记录主结论、时间/因果链末端和同槽表达层集合；`resolveContinuationAnchors()` 按本轮问法选择所需焦点。“依据 / 反证 / 原话”回到主结论，“后来 / 为什么 / 还有相关的吗”从链末端继续，“可靠吗 / 你确定吗”把同槽表达层交给现有验证层优先规则。状态、范围和表达层补全不会因为展示顺序改变续问指代；旧轨迹仍兼容原单焦点字段。实际选择角色和原因位于 `trace.metadata.continuationSelection`。

“有什么依据 / 怎么知道的”只展开当前焦点一层直接 `supported_by`，因此高层结论可以先披露支持它的事件或事实。“原话 / 当时怎么说的”才沿严格有向证据链最多下钻两层寻找 `utterance`；只有命中直接原话后，才可通过 `followed_by` 补一条附近的对方话语恢复交流语境。没有对应层级时会明确返回未找到，不使用普通关联、共同实体或邻近事件凑数。实际披露的记忆 ID 位于 `fragments[].evidenceIds`、`graph.evidenceMemoryIds` 和 `trace.metadata.evidenceMemoryIds`；路线审计仍不包含正文。

“有什么反证 / 反例 / 相反依据”是独立的 `counterevidence` 意图，只展开当前焦点一层直接 `challenged_by`。普通依据不会自动混入反证，反证也不会借用相似或相邻记忆；两者都使用同一套证据 ID 与预算审计。

“这个判断可靠吗 / 你确定吗 / 有没有例外”进入独立的 `evidence-review` 复核意图，同时显示一条最强直接支持与一条最强直接反证。每侧只从当前焦点的一跳审核边中选择，按 `weight × confidence` 排序，平手时优先较新的事件；缺少某一侧时明确说明未找到，不用别的关系补齐。两侧 ID 分别位于 `graph.supportEvidenceMemoryIds`、`graph.counterevidenceMemoryIds` 和对应轨迹元数据。

## 认知来源提示

状态节点优先说明它属于主体自述、可撤销推断还是聚合验证层。非状态节点只在具备来源边时，依据逐来源 `authority` 说明本人陈述、参与者陈述、直接观察、外部记录、逐字记录、转述或模型推断。`manual` 与 `imported` 只是整理和迁移渠道，不会被解释成事实更可信；旧资料缺少完整来源分级时会明确保守提示。

来源提示只进入最终注入文本，不复制到路线审计。旧版只读数据库缺少来源表或字段时保持可召回，不会为了生成提示而要求迁移或写库。

## 因果关系视图

普通召回、时间线和自由联想都不会读取因果边。只有明确的因果问法才进入因果视图：

- “为什么 / 什么导致了这件事”从结果沿人工接受的有向 `causes` 边反查原因；
- “这导致了什么 / 有什么影响”从原因沿同一类边正向读取已经记录的结果；
- 两个方向分别标注原因和结果，不用时间先后、语义相似或常识推断补出缺失因果。

这里的正向召回只是读取数据库中已有且已审核的后续结果，不预测尚未发生或尚未记录的未来。

## 已审核学习状态

召回默认完全忽略 `memory_accessibility_state` 与 `memory_edge_relation_utility_state`，即使数据库中已有数值也不会偷偷改变结果。只有调用方在 `options.plasticity` 中显式设置 `enabled: true`，并完整提供配置版本、允许读取的节点/边策略版本、两类中性值和最大影响幅度时，正式应用过的状态才会生效。缺少 `last_applied_at`、观察窗口、匹配策略版本或任一必需配置时保持原排序，不猜默认值。

节点可访问性只作用于已经通过词法、向量、实体等门禁的普通种子候选：以中性值为零点，最多加减调用方给定的候选分数。它不能让本来无关的节点获得准入，也不修改置信度、重要性、主体、时态或事实真值；日期和显式续问锚点仍是确定性路线。

关系效用按本轮 `timeline`、`associative` 或 `causal` 视图读取，只以有界倍率调整普通边的传播强度。`corrects`、`supersedes`、`established_from`、`completes`、`cancels` 与 `scoped_exception_to` 等真实性补全边忽略学习倍率，避免低使用率把当前状态或纠正事实截断。实际采用的配置、节点加减项和边倍率只进入数值审计；影子候选与未应用变化永不参与召回。

```js
options: {
  plasticity: {
    enabled: true,
    configurationVersion: "retrieval-plasticity-v1",
    memory: {
      neutralValue: 0.5,
      maximumScoreAdjustment: 0.2,
      allowedPolicyVersions: ["memory-policy-v1"],
    },
    edge: {
      neutralValue: 0.5,
      maximumMultiplierAdjustment: 0.4,
      allowedPolicyVersions: ["edge-policy-v1"],
    },
  },
}
```

上面的数值只是接口形状示例，不是产品默认值；正式值必须先由真实观察窗口与固定评测校准。

## 显式授权的情绪排序偏置

正式的 `affective_association` 只记录“某个触发对象与某种情绪存在联结”，不会自动改变召回。要让它参与排序，必须同时满足两层授权：

- 数据库中该状态的最新 `memory_affective_activation_decisions` 记录由人类明确启用，且批准策略版本和表示层在本轮允许列表中；
- 调用方在本轮 `options.affectiveBias` 中显式提供当前情绪、匹配方式、主体和最大影响。

启用后也只会给已经通过普通词法、向量或实体门禁的候选增加有界分数。候选必须通过结构化实体链接与情绪状态的触发对象精确对应；实现不会扫描标题或正文猜触发物，也不会凭情绪把原本未入围的记忆加入候选。日期过滤、显式续问锚点、主体门禁、状态换代、事实置信度和持久边权均不受影响。多个情绪联结同时指向同一候选时取最强单项，不叠加突破本轮最大值。

```js
options: {
  affectiveBias: {
    enabled: true,
    configurationVersion: "affective-retrieval-v1",
    subjectRole: "user",
    subjectKey: "user",
    currentEmotion: {
      label: "开心",
      valence: "positive",
      intensity: "high",
    },
    matchMode: "exact-label",
    maximumScoreAdjustment: 0.1,
    allowedPolicyVersions: ["human-affective-v1"],
    allowedRepresentationLayers: ["reported"],
  },
}
```

该示例只说明必需字段，不代表推荐分值。审计只保存配置/批准记录/记忆/实体 ID、数量和数值调整，不复制情绪状态正文；默认不提供该配置时完全关闭。

## 注入预算

`maximumContextChars` 包含标题、安全指导语和记忆正文。召回器会先扣除固定前缀，再把剩余预算分给每个已选关系链节点、状态补全段和证据段，因此 `selectedMemoryIds` 中的节点不会仅因位于尾部就被静默截掉。`outputBudget` 与 `trace.metadata.outputBudget` 只记录总额、正文额度、格式化前后字符数和兜底截断是否触发，不复制记忆正文。

`retrieveMemories()` 的 `seedRouting` 以及 `trace.metadata.seedRouting` 会保留：

- 计划和实际执行的路线；
- 各路线状态；
- 候选的放行方式；
- 每条命中路线的强度、原始分数和有界分数；
- 最终主种子 ID。

该审计信息只保存记忆 ID 和数值，不复制候选正文。正式候选完整保留，额外的弱汇聚候选最多保留 10 个，其余只记数量，避免长期轨迹被诊断数据无意义撑大。正文只存在于正常候选/上下文返回值中。

## 向量失败

向量提供方不可用时返回 `vector.status = "error"` 和警告，并继续使用词法与实体路线。错误不会让弱候选自动放行，也不会让整次召回失败。
